# PerchPi v1.1 plan

*Draft for review, 1 November 2026. Target: December 2026. Nothing here is built yet.*

v1.1 is a new flashable image for the Raspberry Pi 5. It fixes v1's known issues, puts the Setup Guide and User Manual on the memory card, and folds in what setting up a second station in October 2026 taught us. It keeps v1's install route: Raspberry Pi Imager 2.0 or newer with PerchPi's custom content repository. There is no official Imager listing and no in-app updater.

This document is meant to be argued with. Where there is a real choice, both paths are side by side with a recommendation. Section 7 lists what still has to be decided.


## 1. Already done, so not v1.1 work

The first half of the October split plan (fix the public install steps without a new image) is finished:

- **README install steps** are rewritten: Imager 2.0+, the content-repository URL, the "don't use *Use custom*" warning, the Mac and Linux one-liners.
- **The parts list** names the exact tested parts: Raspberry Pi 5 **8 GB (tested)**, the official Active Cooler and 27W supply, a Samsung microSD (64 GB, 128 GB also good, because detections accumulate on the card), the Clippy EM272 in a UGREEN US205. It carries the warning that a different microphone may leave detection severely degraded or nearly useless. No UPS is listed or recommended.
- **The microphone hood** (the ~39 mm tall version with the thin curved lip) is shared in `hardware/em272-hood`, with STL, 3MF and print settings.
- **The setup video** and the **New User Audio Companion** audiobook are linked from the README.
- **The Chromium kiosk flags** `--disk-cache-size=52428800 --disable-component-update --disable-extensions` are already in the v1 image. `newinstaller.sh` at commit `12110fb`, which the v1 image was built from, writes them into the kiosk's labwc autostart (lines 1790 to 1792). v1.1 only has to keep them. A station installed or hand-patched *before* that commit still needs them added by hand.

This pull request also does the docs half of the plan that doesn't need a new image (see section 5).


## 2. What changes in the image

| # | Change | Why | Image | Docs |
|---|---|---|---|---|
| 1 | **Backup includes the settings file, and Restore keeps it a symlink** | v1 Backup stores only the `birdnet.conf` link; Restore can turn the link into a separate copy | Backup dereferences `/etc/birdnet/birdnet.conf`; Restore writes into the target and leaves the link | Remove the "write your settings down" warning; add "Moving to v1.1" |
| 2 | **Photo uploads up to about 16 MB** | v1 fails over 2 MB (PHP default) | PHP-FPM drop-in raising `upload_max_filesize` and `post_max_size` | Remove known issue |
| 3 | **Password on the species-image API**, except from the station itself | v1 answers `/api/v1/image/…` to anyone on the network, and a caller can grow the image cache | Caddy or PHP check; loopback (kiosk, notifications) still passes | Remove known issue |
| 4 | **Installer error trap** | `newinstaller.sh` exits silently when a step fails | `trap … ERR` that prints the step, line and log path | Hobbyist section: where the log is |
| 5 | **Clean first boot** | cloud-init's package step fails (`apt-get update` exits 100) and `systemctl --failed` lists two units | Fix the apt sources the first boot sees, or turn off cloud-init's package step in the image | Remove known issue |
| 6 | **Guide and manual on the card** | First-timers need them before the station is on the network | See choice B | Setup Guide section 0: "the guide is on the card" |
| 7 | **Perch-score quarantine gate** | Idea from the second station | See choice A | Manual: "Reviewing Quarantine" gains the new reason |
| 8 | **Fixes from the second station** | October 2026 | List not yet confirmed (section 7, question 1) | As needed |
| 9 | **Version names** | Imager shows "PerchPi v1" | `perchpi-os-list.json` and the image name say v1.1 | Every "PerchPi v1" in the steps |

**Candidate, decide in session 1:** clear the password hash from `/boot/firmware/user-data` after the first boot. Every Imager-written Raspberry Pi OS card keeps it, so this is hardening, not a bug fix. The risk is cloud-init behaving differently on later boots, so it needs its own test on the bench Pi.

**Out of scope for v1.1:** an in-app updater, an official Imager listing, NVMe boot from the image (works on the developer's station, still untested from the image), File Manager and Adminer, turning the web terminal back on, any UPS.


## 3. Choice A: the Perch-score quarantine gate

Today a detection goes to Quarantine only when the geomodel says the species is very unlikely for the place and week. The Perch v2 worker already scores every detection and writes `accept`, `reject` or `ambiguous` into `ai_decisions`, but that verdict hides nothing. The gate would let a Perch `reject` quarantine the detection too.

| | **Path 1: the gate quarantines** | **Path 2: shadow only** |
|---|---|---|
| Mechanics | After the worker writes a `reject`, it inserts the detection into `quarantined_detections` with reason `perch-reject`. Only species with a derived per-species false-positive threshold are gated; every other species stays observational. Unhide and Delete work as today. | Keep the verdict observational. Show a small "Perch disagrees" mark on the detection and count the rejects on Quarantine's page, without hiding anything. |
| Cost | Worker change, a reason label in the Quarantine UI, an Advanced Setting to turn it off, one migration for the setting | UI mark and a count; no data-flow change |
| Risk | Real birds hidden from new users, who rarely open Quarantine. The per-species thresholds come from the developer's yard and may not carry over to other stations and microphones. The worker runs about a minute after a detection, so a bird can appear on Overview and then vanish. | False positives stay in the lists, as in v1 |
| Open questions | Does the idea from the second station match this, or was it a Perch logit threshold combined with BirdNET confidence? What fraction of detections would it have hidden there? | None |

**Recommendation: Path 1, built in, but off by default in the public image for v1.1,** with an Advanced Setting to turn it on. Turn it on at the developer's station and the second station, compare a month of gated detections against what you'd have kept, and decide the public default in v1.2. That keeps the public behaviour the same as v1 while the thresholds prove themselves on more than one yard.


## 4. Choice B: where the manual lives on the card

| | **Path 1: the boot partition** | **Path 2: served by the station** |
|---|---|---|
| Mechanics | Put `PerchPi-Guide.pdf` and a short `README-PerchPi.txt` on `/boot/firmware`, the FAT partition any Mac or Windows computer shows after Imager finishes | A **Help** item in the gear menu that opens the manual from the station (`/help/`), plus a link to the latest copy on GitHub |
| Cost | A copy step in the image build; a few MB of the 512 MB boot partition | A route and its symlink into the Caddy web root (`homepage/` files need one, or Caddy answers 200 with the shell), and the PDF or rendered pages in the image |
| Risk | The card copy goes stale against GitHub; Raspberry Pi OS updates rewrite some boot files, though not extra ones | Only helps once the station is on the network, which is exactly when a first-timer needs it least |

**Recommendation: Path 1, plus a gear-menu Help link that opens the User Manual on GitHub.** The card copy covers the moment before first boot. The link is a one-line menu change, always current, and needs no new served files. The station already needs the internet for photos and weather.


## 5. Choice C: moving from v1 to v1.1 with your data

v1 has no updater, so v1.1 means writing a new card. Users keep their detections only if Backup and Restore work, and in v1 that is exactly the broken part.

| | **Path 1: fixed Backup and Restore** | **Path 2: a one-shot migration script** |
|---|---|---|
| Mechanics | On v1: Backup data. Flash v1.1 on a new card (or the same one). On v1.1: Restore data, then re-enter the settings v1's backup doesn't hold (location, web password, site name, BirdWeather token, retention days) | A script run over SSH on v1 that exports the database, recordings and settings to a USB stick; v1.1 imports it on first boot |
| Cost | Fix #1 above plus a v1-backup compatibility path in Restore | A new script, a first-boot hook and its tests |
| Risk | Re-entering settings by hand; large backups through a phone browser | SSH-only, so first-timers can't use it; more first-boot code that only runs once |

**Recommendation: Path 1.** The release notes and manual say plainly that settings from v1 must be typed in again. Using a fresh card is recommended, so v1 stays bootable as a fallback. Test it with a real v1 backup in the restore drill.


## 6. Docs changes

**In this pull request (accurate for v1, no new image needed):**

- README: a clearer install section with one path for most people and a "Comfortable with a Raspberry Pi?" path, an Upgrading section, and a link to this plan.

**With the v1.1 image:**

- "PerchPi v1" becomes "PerchPi v1.1" in every Imager step.
- Remove the fixed known issues.
- Replace the backup warning with the new Backup and Restore behaviour and a "Moving from v1" section.
- The quarantine gate's reason and setting in "Reviewing Quarantine".
- Regenerate `PerchPi-Guide.pdf` from the Markdown and copy it to the card.

## 8. Session checklist

1. **Decide (short).** Answer section 7. Lock the scope table. Commit this plan to the dev repo's design-doc folder before any build.
2. **Fixes in the dev repo.** Backup and Restore with the settings file and the v1-backup path; upload limit; species-image API gate; installer error trap; clean cloud-init first boot. `php -l`, ruff and shellcheck through the pre-commit gate. Session log entry.
3. **Perch gate.** Per choice A: setting, worker change, Quarantine reason label. Turn it on at the developer's station and run it for a week.
4. **Docs on the card.** Copy the guide to the boot partition; add the Help link; regenerate the PDF; bump version names.
5. **Build and test on the bench Pi.** A fresh install run to make the image source. Then write it with Imager and its customisation, and check: microphone capture, kiosk, the web password change, location, a test bird, Backup then Restore from a **real v1 backup**, the quarantine gate off by default, `systemctl --failed` empty, and the kiosk profile's size after 24 hours.
6. **Publish.** Release `v1.1-YYYYMMDD` with the image, `perchpi-os-list.json`, sizes and both sha256s, and the commit it was built from. Update the README and guides in the same pass. Check the content-repository URL still resolves to the new image.
